# Echo Attribute Specification (Prototype 0.x)

Status: Finalized for Prototype acceptance

Scope:
- Gameplay rule specification only
- No implementation details
- Linear deterministic slot execution
- Compatible with the current seven core attributes and 28-object framework

---

## 1) Purpose

Echo re-executes the immediately previous successfully executed eligible real attribute handler exactly once.

Echo exists to create deterministic replay-based ordering decisions without introducing branching, rollback, or randomness.

---

## 2) Runtime Context

Echo operates within the current linear runtime model:

- `RV`
- `StoredRV`
- `damage`
- `started`
- `ended`
- `reactionState` (`stable` / `charged`)

Echo does not add new resource pools.

---

## 3) Preconditions

- Echo requires Ignite to have already started the reaction.
- Echo is invalid after the reaction has ended.

Error behavior:

- Echo before Ignite returns `ERR_PRECONDITION`.
- Echo after Explode returns `ERR_INVALID_STATE`.

No post-terminal exception is introduced.

---

## 4) Source Selection

Echo selects the source using this strict rule:

- Source must be the **immediately previous real executed attribute**.
- Echo does not search backward past that immediate previous real attribute.

If that immediate previous real attribute is missing, unsuccessful, or ineligible:

- Echo succeeds as a deterministic no-op.
- Echo returns no error.

---

## 5) Replay Semantics

When a valid source exists:

1. Echo reuses the source attribute's exact params.
2. Echo re-executes the source handler against **current runtime state**.
3. Normal state mutation rules apply.
4. Existing source-handler preconditions and errors remain valid.

If source replay fails:

- Echo fails with replay context.
- First-error-stop behavior is preserved.
- No rollback occurs.

Echo repeats **handler behavior**, not recorded numerical deltas.

---

## 6) Eligible and Ineligible Sources

Eligible source attributes:

- `amplify`
- `store`
- `release`

Ineligible source attributes:

- `ignite`
- `charge`
- `echo`
- `explode`
- synthetic handler execution created by Echo

---

## 7) Charge Interaction

Echo itself:

- is not Charge-eligible
- does not consume Charged

Replayed source handler follows normal current-state rules:

- replayed Amplify can consume active Charge
- replayed Store can consume active Charge
- replayed Release does not consume Charge

If the original eligible step already consumed Charge, replay normally sees `stable` unless another Charge occurred in between.

---

## 8) Recursion Prevention

- Echo cannot target Echo.
- Echo cannot target synthetic replay generated by Echo.
- Replay result does not become an Echo source.
- No recursive dispatch is allowed.

Consecutive Echo behavior:

- First Echo may replay immediately previous eligible real attribute.
- Second Echo sees previous real attribute as Echo (ineligible) and becomes a valid no-op.

---

## 9) Logging Requirements

Preserve all normal simulation log fields.

Every Echo log entry must include:

- `echoApplied`
- `echoSourceStep`
- `echoSourceSlotIndex`
- `echoSourceObjectKey`
- `echoSourceAttribute`
- `echoSourceAttributeIndex`
- `echoNoopReason`
- `echoReplaySucceeded`
- `echoReplayErrorCode`

Use `nil` where no source exists.

The normal before/after fields of the Echo step must reflect the combined state transition caused by replay behavior.

Echo replay should not create a separate top-level simulation step.  
Replay context is recorded inside the Echo step log metadata.

---

## 10) Failure Behavior

- No eligible source: successful no-op.
- Source replay succeeds: Echo succeeds.
- Source replay handler fails: Echo fails.
- First-error-stop behavior remains.
- Prior successful state mutations remain visible.
- No rollback.

---

## 11) Acceptance Scenarios (Given / When / Then)

Unless otherwise stated, scenarios assume current prototype baseline:

- Spark (Ignite) starts reaction
- Fuel = Amplify
- Crystal = Store
- Valve = Release
- Catalyst = Charge
- Mirror = Echo
- Bomb = Explode

Initial state:

- `RV = 0`
- `StoredRV = 0`
- `damage = 0`
- `started = false`
- `ended = false`
- `reactionState = stable`

---

### Scenario 1: Spark -> Fuel -> Mirror -> Bomb

Given that chain  
When executed  
Then:

1. Spark sets `RV=1`
2. Fuel amplifies `RV=2`
3. Mirror replays Amplify using original Fuel params on current state: `RV=4`
4. Bomb resolves with final state

Expected:

- Amplify replay occurs once
- `RV` progression: `1 -> 2 -> 4`

---

### Scenario 2: Spark -> Crystal -> Mirror -> Bomb

Given that chain  
When executed  
Then:

1. Spark sets `RV=1`
2. Crystal stores once: `StoredRV=1`
3. Mirror replays Store with same params: `StoredRV=2`
4. Bomb resolves

Expected:

- `StoredRV` progression: `0 -> 1 -> 2`

---

### Scenario 3: Spark -> Crystal -> Valve -> Mirror -> Bomb

Given that chain  
When executed  
Then:

1. Spark: `RV=1`
2. Crystal: `StoredRV=1`
3. Valve (Release Full Merge): `RV=2`, `StoredRV=0`
4. Mirror replays Release on current state:
   - `StoredRV=0`, so replayed Release is a valid no-op
5. Bomb resolves

Expected:

- Replay is safe no-op
- `StoredRV` never becomes negative

---

### Scenario 4: Spark -> Catalyst -> Fuel -> Mirror -> Bomb

Given that chain  
When executed  
Then:

1. Catalyst sets `charged`
2. Fuel executes as charged eligible attribute and consumes Charge
3. Mirror replays Amplify on current state
4. Replay sees current state (normally `stable` unless recharged)

Expected:

- Echoed Amplify executes in current Stable state under this chain

---

### Scenario 5: Spark -> Catalyst -> Valve -> Mirror -> Fuel -> Bomb

Given that chain  
When executed  
Then:

1. Catalyst sets Charged
2. Valve executes Release and does not consume Charged
3. Mirror immediate source is Release (eligible), so Mirror replays Release
4. Echo and Release do not consume Charged
5. Fuel later consumes Charged as the next eligible Charge consumer

Expected:

- Charged persists through Valve and Mirror
- Fuel consumes Charged

---

### Scenario 6: Spark -> Fuel -> Mirror -> Mirror -> Bomb

Given that chain  
When executed  
Then:

1. First Mirror replays Amplify
2. Second Mirror checks immediate previous real attribute (Echo), which is ineligible
3. Second Mirror is valid no-op

Expected:

- no recursion
- deterministic no-op on second Echo

---

### Scenario 7: Spark -> Mirror -> Bomb

Given that chain  
When executed  
Then:

- Mirror has no eligible immediate previous real source
- Mirror succeeds as deterministic no-op
- no error

---

### Scenario 8: Mirror before Ignite

Given a chain where Mirror executes before any Ignite  
When Mirror executes with reaction not started  
Then:

- return `ERR_PRECONDITION`
- behavior is consistent with other state-dependent attributes

---

### Scenario 9: Deterministic repeated simulation

Given identical stage slots, object data, and parameters  
When simulation is run multiple times  
Then every run must produce identical:

- final results
- ordered log entries
- Echo source selection/replay outcomes

---

### Scenario 10: Runtime reset between simulations

Given a previous run with Echo replay activity  
When a new run starts  
Then:

- no prior Echo source/replay context carries over
- runtime state resets normally

---

## 12) Edge Cases

- Immediate previous real attribute exists but failed: Echo no-op.
- Immediate previous real attribute exists but ineligible: Echo no-op.
- Echo after terminal attribute is not executed due to termination boundary.
- Replayed Release with `StoredRV=0` is valid no-op.
- Replayed handler failures propagate as Echo failure (no rollback).

---

## 13) Dual-Object Catalog Decisions

Finalized execution orders:

- Resonator: `Amplify -> Echo`
- Memory Crystal: `Store -> Echo`
- Pulse Valve: `Echo -> Release`
- Kaleidoscope: `Echo -> Charge`
- Cluster Bomb: `Echo -> Explode`

Finalized combination:

- Resonant Spark: `Ignite -> Echo`
- no Ignite-specific Echo exception is added

Important testing constraint:

- Resonant Spark replaces the normal Spark/start object when tested.
- A chain containing both Spark and Resonant Spark is not a valid design example.

## Finalized Behavior Summary

Echo is a deterministic one-step handler replay mechanic:

- It can replay only the immediately previous successful eligible real attribute.
- It uses that source params and current runtime state.
- It does not recurse and does not replay synthetic Echo results.
- It is safe no-op when no valid source exists.

## Deferred Issues Summary

- No terminal-rule exception for post-Explode execution.
- Echo interactions beyond current core scope remain deferred.
